# Geospectrum Technologies — QA Co-op

## Overview

I worked at Geospectrum Technologies as a QA Co-op Student from September 2025 through December 2025.

Geospectrum Technologies works with marine and spatial technologies, and my role provided experience working within a technical environment involving specialized software and systems.

My work focused on quality assurance and testing, giving me experience understanding software behavior, identifying issues, documenting problems, and working with developers and technical team members.

## Quality Assurance

My primary responsibility was software quality assurance.

I tested software functionality to identify bugs, unexpected behavior, and potential issues before software was released or delivered.

This required understanding the intended behavior of software and comparing it with the behavior observed during testing.

I worked through test scenarios and investigated unexpected results rather than simply checking whether an application appeared to work.

## Projects

The main projects I got to work on included:

1. Mission Server. I took an exisiting outdated mission server simulator, contacted the team that created the mission server and went through and attempted to understand the new changes and code, updated the mission server accordingly then wrote tests around all the mission server functionalities that were added to the everyday test suite.

2. PLC simulator. I took an existing PLC simulator and added and HTTP Fast API to it so non technical users could interact wit hthe PLC server through curl commands on a running server instead of needed to set everything up and interact through the Python shell. This taught me a lot about multi-threading and server API's.

3. Squish GUI testing. I worked on refacting how we used Squish GUI testing code to make everything use inheritence properly and widget instead of being hard coded.

## Testing and Debugging

My QA work involved systematically reproducing issues and determining the conditions under which they occurred.

When an issue was identified, I worked to provide enough information for developers or other technical team members to understand and reproduce the problem.

This involved paying attention to:

* Expected behavior
* Actual behavior
* Steps to reproduce
* Test conditions
* Error behavior
* Edge cases
* Regression issues

Working in QA helped me develop a more systematic approach to software testing and debugging.

## Working With Technical Systems

The role required me to understand software beyond the surface-level user interface.

Testing specialized technical software often required understanding how different components of a system interacted and considering how changes in one part of the system could affect other functionality.

This experience strengthened my ability to approach unfamiliar technical systems, learn how they work, and identify potential problems.

## Collaboration

I worked as part of a technical team and communicated issues and findings to other members of the team.

A useful part of the experience was learning how to communicate technical problems clearly enough that another developer or team member could reproduce and investigate them.

This helped me understand QA as more than simply finding bugs; effective QA involves communicating useful technical information that helps improve the software.
